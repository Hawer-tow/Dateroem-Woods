Creation order below is dependency-safe (every FK target already exists
by the time it's referenced). USERS is created right after ROLE (its only
dependency) so every later table can safely FK its Deleted_By to USERS.
Exception: ROLE has no FK on Deleted_By since it's created before USERS.

ROLE, USERS, FARMER, REMAINDER_TREES, TRIP, VEHICLE, MACHINE, SMS_QUEUE,
CAMPAIGN, TREES, FINANCIAL_TRANSACTION, PRODUCTS, ORDERS, PROFIT,

BULK_TRIP_PRODUCTION_DESCRIPTION, LOAN_REPAYMENTS

DateroemWoodSales (mobile app) - Kotlin + Jetpack Compose (Material3), Retrofit + OkHttp + Gson for REST/JSON calls to the backend. Already scaffolded in Android Studio (com.dateroem.woodsales, minSdk 24, targetSdk 35).

backend - Java, Spring Boot. Spring JDBC (JdbcTemplate) / MyBatis for calling the MySQL stored functions and procedures directly (fn_trip_profit, sp_recalculate_trip_profit, etc. from dateroem_functions_procedures.sql) rather than JPA/Hibernate, since those are built around entity mapping and are awkward for calling stored routines. JPA may still be used for plain CRUD entities if convenient. Exposes REST/JSON APIs consumed by the mobile app, the frontend server, and mobileServer.

frontend (server) - Python, FastAPI. Acts as a BFF/caching layer between the React website and the Java backend: serves the built React static bundle, caches read-heavy data (e.g. via Redis) to keep the site responsive if the backend is briefly unavailable, and proxies writes through to the backend API. Uses the existing dateroem_frontend MySQL user (SELECT-heavy, limited INSERT) for any direct cached reads.

frontend (UI) - React (Vite build), the actual website the public/customers see. Talks to the Python frontend server's API, not directly to the Java backend.

mobileServer - Python, FastAPI. Same caching/stability role as the frontend server, but serving the Kotlin mobile app instead of the website - absorbs peak-hour load and serves cached/simplified data so the mobile app stays responsive if the Java backend is under load. Uses the existing dateroem_mobile MySQL user for any direct cached reads.

admin_server_control - Kotlin, Compose Multiplatform Desktop (planned; built after the other servers are running). Chosen to reuse the same language/UI paradigm as the Android app and to interoperate directly with the JVM-based Java backend. JavaFX is the fallback if Compose Desktop tooling proves inconvenient.

All inter-service communication is intended to use public/private key encryption (keys already prepared: mobile2serverencryption_decription_private_key.pem / _public_key.pem).
